# ManaScout working rules

- Work on `DEVELOPMENT`, the primary development branch. `DEVELOPMENT-2` is the synchronised backup; update it only by a verified, authorised fast-forward.
- Never modify `main`, force-push, rewrite history, delete branches, or automatically create or merge pull requests.
- Inspect current remote heads and preserve existing and unrelated work. Commit focused, validated changes directly to `DEVELOPMENT` using the GitHub connector when shell Git networking is unavailable.
- Preserve existing card guides, URLs, homepage, search, Card of the Week, foil effects and printing explorer.
- Read relevant files once where practical; avoid repeated full-repository audits.
- Use focused, maintainable HTML, CSS and JavaScript. Keep Deck Studio styles scoped; do not change the rest of the site's palette.
- Prioritise mobile usability, accessibility and performance. Respect reduced-motion preferences and keyboard navigation.
- Validate affected behaviour and report actual outcomes and environment limitations. Do not repeatedly retry blocked network, socket or browser operations.
- Never fabricate card data, artists, finishes, legality, prices or successful tests. Clearly distinguish selected cards from cards added to a deck.
- Respect the authorised phase. Disabled future controls must be labelled honestly; do not advertise unfinished functionality as available.
