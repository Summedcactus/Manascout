# Monetisation setup

ManaScout’s first commercial priority is retailer and affiliate exits. A visitor verifying a set, art or foil treatment is already considering a specific purchase. Display ads are a second option, with premium networks a later migration decision after the site can demonstrate real traffic and eligibility.

## Status

**Ready to apply** means the owner can prepare or submit an application subject to current eligibility. **Approved** requires the provider’s confirmation. **Integrated** means the approved provider’s configuration is in the application. **Live** requires a released integration and verified real traffic or transactions. This branch contains a general publisher, link and measurement foundation. No network below has verified approval or live serving from this phase. Cardmarket is an ordinary outbound link, and the existing Google publisher identifiers establish neither ad serving nor account approval.

The public Magic Madhouse and Chaos Cards programme sources were verified. Attempts to verify a current live name-search result for either retailer were inconclusive, so their route definitions are intentionally unset. Cardmarket retains the existing catalogue product path or name search for live selections, with attribution parameters removed from incoming catalogue links. A retailer should confirm edition, language, finish, condition and stock. Scryfall links are for verification and have no merchant event identity.

For future same-site affiliate parameters, use the `affiliateParameters` map in [retailers.js](../assets/js/retailers.js). Set only approved public values for a configured retailer. Keep credentials and affiliate account tokens out of the repo. The renderer labels affiliated links, adds the sponsored relationship and links to About's disclosure. A network redirect template or exact-printing feed needs explicit host and product verification before use.

## Analytics activation

The public setting to obtain for GA4 is **the real web stream measurement ID**, stored as `ga4MeasurementId` in [analytics-config.js](../assets/js/analytics-config.js). It is currently `null`, with the provider disabled. Plausible remains available through the original bounded adapter. Any activation requires a separate release and an owner-controlled account. [Existing analytics contract](product-analytics.md)

- GA4 uses the same validation layer as Plausible. Route identity is built from a published pathname and external referrers are reduced to an origin. The adapter sends manual pageviews and validated events. The `merchant_exit` event carries only a configured merchant ID, guide slug, a printing-ID-present boolean and a bounded finish. A retailer search or exit does not report a purchase.
- GA4 tag loading and consent handling belong to a future approved integration. To connect it, provide a consent-managed `gtag` function before analytics initialises and a `window.ManaScoutAnalyticsConsent.ga4Ready(measurementId)` callback. Return true only for the verified stream with consent granted and Enhanced Measurement disabled. The bridge owns denial, later grants, revocation and disabling or removing the provider as appropriate. No Google tag loader, consent UI or analytics script from a network is shipped here.
- When testing a real integration, use a separate approved stream first. Disable automatic pageviews, history events, outbound tracking and other Enhanced Measurement features in the stream, and leave ad-personalisation features off. Inspect actual network payloads for canonical `page_location` and origin-only referrers. Exercise query and hash Search, comparison and Deck URLs, cookies and consent changes before activation. An external SDK or CMP can collect data independently of these adapter commands, so the network check is part of integration acceptance. [GA4 pageviews](https://developers.google.com/analytics/devguides/collection/ga4/views) · [Google tag privacy controls](https://developers.google.com/tag-platform/security/guides/privacy)
- Update the privacy notice and use an appropriate CMP for the intended audiences and providers. For Google publisher advertising, verify and meet the certified CMP requirements that apply to UK, EEA and other covered users. The application hook is an integration boundary. [Google publisher consent requirements](https://support.google.com/adsense/answer/13554116)

## Placement, release and verification

Test one restrained placement at a time if display ads are approved. Keep ads away from Search, printing selectors, card artwork, comparison controls, editor actions and primary navigation. Preserve keyboard focus, small-screen layouts and performance. Avoid automated overlays, popunders, forced redirects, push prompts and empty production slot reservations.

Keep the existing Google record in `ads.txt`. Add a seller row only after the provider supplies it for the verified site. Check the served file, labels, network activity, consent rejection and site usability separately from provider approval. Report application, approval, integration and live serving as distinct states. Verify paid affiliate activity against provider reporting before treating exits as revenue.
